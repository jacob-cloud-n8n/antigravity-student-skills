# 工作資料夾與可攜契約

當需要初始化、補建、跨平台搬移或健檢 AI 協作系統時讀取。

## 四句硬規則

1. 資料可攜。
2. 平台可替換。
3. 接線可重建。
4. 核心內容不重做。

## 永久資料與接線層

| 類型 | 真相源 | 可否平台專屬 |
|---|---|---|
| 協作偏好與界線 | `profile/我的AI協作檔案.md` | 否 |
| 工作卡、專案需求與驗收 | `projects/`、`templates/` 的實例 | 否 |
| 來源、知識、成果與工作日誌 | 既有第二大腦 | 否 |
| AGENTS.md、CLAUDE.md、Gem Instructions | 專案規則或 `adapters/` | 可以，但只能指向核心資料 |
| Skills、Plugins、MCP、Actions、connector | 平台執行層 | 可以，需保留重建說明與實測狀態 |

正式資料不得只存在 Skill 安裝目錄、某次聊天記憶或只有單一平台能匯出的格式。

## 檔案規則

- 使用 UTF-8 Markdown；附件保留常見原始格式並以 Markdown 索引。
- 內部連結優先使用相對路徑；避免 `/Users/...`、`C:\Users\...` 等機器專屬路徑。
- `index.md` 記錄協作檔案、專案、第二大腦與 adapters 的相對位置。
- Obsidian 可作為閱讀、搜尋與雙向連結介面，但資料夾本身才是真相源。
- 私人資料要不要雲端同步由學員決定；本機保存不代表同意上雲。

## 補建既有環境

若學員已經有 project-init、startup／shutdown 或第二大腦：

1. 唯讀列出現有 AGENTS.md、handoff、二腦索引、工作日誌與相對路徑。
2. 檢查是否已有協作偏好檔；有就提出合併草稿，沒有才新增。
3. 不移動第二大腦、不重建 Git、不批次複製歷史、不覆蓋平台規則。
4. 在 `AI協作系統/index.md` 登記既有路徑。
5. 用下一項真實工作驗證接線，再安排第二項任務測重複性。

## 換平台驗證

搬到另一個 Agent 或平台時：

1. 複製或同步學員選定的工作資料夾。
2. 讀 `index.md` 和 `profile/我的AI協作檔案.md`。
3. 依 `adapters/` 重建該平台最小接線。
4. 對 Plugin、MCP、Actions、外部 API、雲端服務逐項標示：已連接／需另接／不可用。
5. 用一項真實小工作驗證讀取、確認、執行與保存路徑。

檔案能打開不等於搬移完成；必須有真實工作驗證。平台內建記憶、付費功能與外部整合不保證可攜。

## 工具

- 預覽初始化：`python3 scripts/init_workspace.py <工作資料夾>`
- 確認後建立：`python3 scripts/init_workspace.py <工作資料夾> --apply`
- 唯讀健檢：`python3 scripts/audit_workspace.py <工作資料夾或 AI協作系統>`

兩支工具都只使用 Python 標準函式庫。初始化只補缺少檔案；健檢不修改任何內容。
