# 真實工作協作循環

當學員提出要規劃或執行一項真實工作時讀取。第一項工作以「規劃工作」為預設成功案例；不可只做假想練習。

## 十個節點

1. **需求**：用一句話說清楚想完成的結果。
2. **釐清**：只問會改變結果的問題；同一主題最多三輪。
3. **計畫**：拆成小步驟，標示順序、產出與停止條件。
4. **分工**：說清楚學員決定什麼、Agent 可讀／可草擬什麼、哪些動作要再確認。
5. **學員校正**：顯示已知、假設與待確認，讓學員修正。
6. **確認**：在寫檔、執行、對外傳送或改變狀態前取得明確同意。
7. **執行**：只做已確認的最小範圍；遇到新範圍停下來回報。
8. **驗收／退修**：以可觀察標準檢查；技術完成不等於學員接受。
9. **收工與下一步**：記錄做到哪、留下下一個明確動作。
10. **保存建議**：建議哪些來源、知識、成果或踩坑值得放入第二大腦；未確認不寫入。

## 工作協作卡使用法

以 `assets/workspace-template/templates/工作協作卡.md` 為底，一開始只填：成果、期限、輸入、完成標準。計畫確認後再填分工與步驟；執行後才填驗收、退修與保存建議。

不要為了填滿模板而捏造內容。缺少的欄位寫「待確認」，不得寫成已知事實。

## 權限預設

| 動作 | 預設 |
|---|---|
| 讀取學員放在工作範圍內的資料 | 可做，仍遵守專案與隱私規則 |
| 分析、規劃、產生聊天草稿 | 可做 |
| 新增／修改正式檔案 | 先預覽並確認 |
| 執行會改變資料或系統狀態的指令 | 先確認 |
| 上傳、寄送、公開、部署、commit、push | 各自明確確認 |
| 把成果寫入第二大腦 | 提議分類，確認後交給對應流程 |

## 第一次與第二次任務

第一次任務的目標是學會循環，不是一次把所有工具自動化。完成後提供下一步卡：

```markdown
第一項工作：已完成／待退修
這次有效的合作方式：<1-3 點>
要調整的協作檔案：<沒有就寫無；先預覽>
第二項任務：<與第一項不同但真實的小工作>
下次開場句：請使用同一套協作循環，幫我處理＿＿。
```

只有第二項任務也能依相同流程完成，才把該合作方式視為穩定；穩定且可重用的流程可再提議轉成 Skill。
