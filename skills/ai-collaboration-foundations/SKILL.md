# AI 協作基礎

讓學員先建立一份「AI 要怎麼跟我工作」的共用檔案，再把它用在真實工作。核心資料留在學員指定的工作資料夾，平台設定只做接線層，因此換 Agent、換平台或換工作時不必重做核心內容。

## 成功標準

完成時應同時做到：

1. 學員有一份工作導向的 `我的AI協作檔案.md`，沒有被迫提供詳細私人資料。
2. 學員知道目前是第幾步、下一步要做什麼，以及哪些動作需要自己確認。
3. 舊 GPT、Gem、Claude Project 或提示詞被分類為協作偏好、專案資料、參考資料、可重用 Skill 或需另接的平台能力。
4. 學員用工作協作卡完成一項真實工作的規劃、確認、執行與驗收。
5. 學員能用第二項任務重複同一流程；尚未實測第二項任務時只能稱「已建立基礎」，不可稱「已熟練」。
6. 核心資料使用 UTF-8 Markdown、相對路徑與普通資料夾保存；平台更換時只需重接 adapter 並實測。

## 先判斷入口

只問會改變路線的一題：

> 你目前是第一次建立、已經有開工／第二大腦，還是想先匯入以前用過的 GPT、Gem 或提示詞？

依答案走一條主路線，不要求學員先理解術語：

- **第一次建立**：引導採訪 → 預覽協作檔案 → 初始化資料夾 → 第一項真實工作。
- **已有開工／第二大腦**：先唯讀盤點 → 只補協作檔案與索引 → 下一項真實工作；不得重新初始化或搬動二腦。
- **匯入舊 AI 經驗**：先走六步匯入流程，再把確認後的內容放入正確位置。
- **已提出真實工作**：以該工作作為採訪例子，邊做邊補最少必要資料，不把學員擋在表單前。

需要採訪細節時讀 [引導採訪](references/guided-interview.md)；遇到舊 GPT／Gem／Claude Project 時讀 [舊 AI 匯入](references/prior-ai-import.md)。

## 固定導入流程

每次只顯示目前必要資訊，並在段落末尾提供：

```text
進度：第 N/6 步｜下一步：<學員現在只要做的一件事>
```

六步為：

1. **選入口**：確認新建、補建、匯入或直接做真實工作。
2. **取得最少資料**：完成工作導向採訪；已有資料就推定草稿，不重問。
3. **安全與分類**：排除憑證和不必要個資；區分永久資料與平台接線。
4. **預覽**：逐項顯示準備建立或更新的相對路徑、摘要與已知／假設／待確認。
5. **確認並建立**：只有學員確認後才寫檔；已有內容只補缺口、不覆蓋。
6. **做第一項工作**：用工作協作卡跑完循環，最後給「下一步卡」安排第二項重複任務。

沒有得到確認時可以產生聊天中的草稿與預覽，但不得寫入正式檔案。

## 工作資料夾契約

學員選定一個能長期保留的工作資料夾後，建議加入：

```text
AI協作系統/
├── index.md
├── profile/
│   └── 我的AI協作檔案.md
├── projects/
│   └── README.md
├── templates/
│   ├── 工作協作卡.md
│   ├── 專案協作模板.md
│   └── 收工紀錄模板.md
└── adapters/
    ├── codex.md
    ├── claude.md
    └── gemini.md
```

完整欄位與可攜規則見 [工作資料夾契約](references/workspace-contract.md)。可用 `scripts/init_workspace.py <工作資料夾>` 先預覽；只有學員確認後才加 `--apply` 建立缺少檔案。工具永不覆蓋既有檔案。

若已有第二大腦，不搬動、不複製；只在 `index.md` 登記它的相對路徑。若尚未建立而學員明確要求，再交給 `student-second-brain`，不要在本 Skill 另造一套二腦。

## 協作檔案的組裝原則

`我的AI協作檔案.md` 是跨平台真相源；`AGENTS.md`、`CLAUDE.md`、Gem／Custom GPT Instructions 與平台 Skills 是 adapter 或執行規則，不是個人資料庫。

- 協作檔案保存：目前工作、常見任務、熟悉／不熟悉的工具、說明偏好、確認界線、近期目標、禁區與仍待確認事項。
- AGENTS／CLAUDE 只放該專案的硬規則、觸發條件、必要路徑與禁止事項，使用相對路徑指向協作檔案。
- 不把整份協作檔案複製到每個平台設定；需要時按任務讀取相關段落。
- 不依賴平台專屬 import 語法作為唯一機制；更換平台後用一項真實工作驗證接線。

## 真實工作的協作循環

開始規劃或執行工作時讀 [工作循環](references/work-cycle.md)，依序完成：

```text
需求 → 釐清 → 計畫 → 人與 Agent 分工 → 學員校正 → 確認
→ 執行 → 驗收／退修 → 收工與下一步 → 建議是否存入第二大腦
```

預設權限：可以讀取範圍內資料並產生草稿／方案；寫檔、執行會改變狀態的動作、對外傳送、部署、commit／push 及批次整理前要確認。專案已有更嚴格規則時，以專案規則為準。

同一主題最多追問三輪。第三輪後仍不完整時，提供一份可校正草稿，明列：

- 已知事實
- 暫時假設
- 尚待確認
- 建議先做的最小一步

不得因追求完整而讓學員一直回答問題。

## 與既有 Skills 的分工

- `project-init`：建立專案的 AGENTS.md、handoff 與版本基礎；本 Skill 不取代它。
- `startup`／`shutdown`：負責每次工作的接續與保存；本 Skill 提供可引用的協作檔案與工作卡。
- `student-second-brain`：保存來源、知識、成果與日誌；本 Skill 只在工作完成後提出「值得保存什麼」。
- `gpt-role-to-codex-skill`：把已成熟、可重複的顧問／教練角色轉成 Skill；本 Skill 先分類並取得學員確認，再交棒。

建議新學員順序：工作環境準備 → AI 協作檔案 → 一項真實工作 → 專案初始化 → 開工／收工 → 第二大腦 → 把穩定流程做成 Skill。

已經先學過初始化與第二大腦的學員不需重來：唯讀盤點、補一頁協作檔案、在下一項真實工作使用，再測第二項任務即可。

## 安全與隱私界線

- 不主動詢問身分證號、生日、住址、家庭細節、完整健康或財務資料。
- 未成年學員以暱稱、角色與學習需求即可。
- API key、token、密碼、Cookie、私鑰、驗證碼與助記詞不得寫入協作檔案、模板、Skill 或第二大腦。
- 同意本機保存不等於同意同步、上傳、公開、提交 Git 或傳給外部服務；各自需要明確授權。
- 涉及醫療、法律、財務或他人權益時，標示限制、查證來源並保留人工決定。
- AI 不替學員作最終決定，不把推測寫成事實，不把一次性要求升格成永久偏好。

## 交件格式

每完成一個階段，用短版下一步卡回報：

```markdown
目前完成：<協作檔案／舊資料分類／第一項工作／第二項重複測試>
已確認：<1-3 點>
仍待確認：<沒有就寫無>
檔案位置：<相對於學員工作資料夾的路徑>
下一步：<學員現在只要做的一件事>
```

若只產生預覽，必須明說「尚未寫入」。若平台能力沒有實際連接與測試，必須寫「需另接」，不可說已搬移。

## 不該做的事

- 不建立詳細私人身分檔案來換取個人化。
- 不重新初始化既有專案、不移動既有第二大腦、不批次搬聊天歷史。
- 不覆蓋 AGENTS.md、CLAUDE.md、協作檔案或 adapter。
- 不把正式資料藏在 Skill 安裝目錄或某平台的聊天記憶裡。
- 不把 Actions、MCP、connector、雲端硬碟或外部 API 說成能自動跨平台搬移。
- 不在未確認前寫檔、部署、公開、同步、commit、push 或修改知識庫。
- 不把單次工作習慣直接寫成永久規則；先在至少兩項任務驗證。
