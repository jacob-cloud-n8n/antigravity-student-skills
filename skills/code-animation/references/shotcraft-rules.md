## 一、全片四段能量配額（`promo-energy-arc`，預設適用 30–60 秒多功能產品宣傳片）

| 段位 | 時長占比 | 能量等級 | 驗收職責與硬門檻 |
|---|---|---|---|
| **① 品牌開場** | **8–12%**（與 ② 合計可達 **20%**） | 低 | 品牌字標登場落定後靜止停留 **≥ 1 秒**（R1），平穩交棒給產品畫面。 |
| **② 單主角立傳** | **12–15%** | 中（質感最高、節奏最慢） | 全鏡只放 **1 個**主角元素（Q5），走完聚焦→懸浮→歸位完整動作弧 **≥ 3 秒**（R3），搭配原生 `zoom` 高清光柵化（Q2）立出產品最小核心單位。 |
| **③ 功能爬升段** | **55–65%** | 中高 ⇄ 低 交替 | 每鏡綁定 **1 個**獨立功能、每種主動畫手法全片只用 **1 次**（P4）；高能量鏡（發牌飛入／堆疊）與穩節奏鏡（真人速度操作／閱讀）交錯排列，資訊最密的文件／報表鏡排在收場前（倒數第 **2–3 鏡**）。 |
| **④ 發表會收場** | **13–16%** | 峰值（全片最高） | 每個已展示功能各派 **1 個**代表元素自四方飛入圍住品牌字標（Q8），配升降運鏡、舞台光與粒子推至全片最高潮，收尾字標靜止停留 **≥ 1 秒**（R1）。 |

### 配額排程與呼吸字卡驗收要點
- [ ] **呼吸字卡配額**：每 **1–2 個**功能鏡頭後穿插 **1 張**呼吸字卡，全片共 **2–4 張**，單張約 **1.7–1.8 秒**（30fps 下 **50–55 格**）；重要功能出場前兼作前導字卡（C2），且字卡文案不得與收場標語重複（P4）。
- [ ] **先扣停留再排動畫**：分配各鏡時長時，必須先從鏡頭預算內扣除靜止停留時間（關鍵資訊落定 **≥ 1 秒［30 格］**、群體元素排滿尾韻 **≥ 0.5 秒［15 格］**）與轉場重疊時間，剩餘秒數才排動態，禁止排滿動畫後硬塞停留。
- [ ] **短片與單功能例外**：**15 秒**短片或單一功能產品可合併中段，但首段停留（①）與末段能量峰值（④）不可省略；**③ 段禁止連續堆疊高能量鏡**以免淪為視覺噪音。

## 二、27 條審美、運鏡、音效、文案與流程驗收清單

### 節奏（R1–R4）
- [ ] **R1｜關鍵畫面呼吸與字標停滿 1 秒**：承載核心資訊的字卡、數字或網格全貌落定後必須完全靜止 **≥ 1 秒**才切鏡；片頭與片尾的品牌字標（wordmark）各自落定後須停滿 **≥ 1 秒**，不把停頓額度浪費在一般過場卡片。
- [ ] **R2｜非線性加速＋物理隱喻＋收尾停 0.5 秒**：所有飛入與捲動一律採用非線性緩動與非均勻錯峰（嚴禁等速直線運動）；大量同類元素進場須綁定物理隱喻（如牌堆發牌）並呈「越來越快」硬加速，排滿畫面後靜止 **≥ 0.5 秒**再進下一拍。
- [ ] **R3｜節奏寧慢勿快、主體動作弧 ≥ 3 秒**：初版時間軸預設放慢一檔；開場主體完整動作弧（聚焦→懸浮→歸位）時長 **≥ 3 秒**；打字、搜尋篩選、點擊等互動展示須按真人實際操作速度進行，確保觀眾第一次看就能跟上步驟。
- [ ] **R4｜全片畫面級節拍衝擊 ≤ 3 處**：音樂對拍只管切點時機，禁止隨鼓點逐拍震動全畫面——作用於整畫面或相機層的大衝擊（全畫面縮放泵動、震屏、閃白格、負片格）全片 **≤ 3 處**（單一套招如三連閃計為 **1 處**），須對準全片最強重拍且相鄰兩處間隔 **≥ 16 拍**；節拍泵連打單次 **≤ 4 拍**、全片 **≤ 1 次**；其餘拍點只動主角元素層。

### 質感、運鏡與構圖（Q1–Q11）
- [ ] **Q1｜既有頁面一律實截、敏感資料全面去識別**：呈現既有產品介面必須用無頭瀏覽器截取真實畫面（整頁貼圖＋元素獨立裁切＋座標 JSON），禁止手刻假 UI 仿造既有頁面；僅非復刻場景（抽象開場、品牌段、原頁不存在的展示元件）可手刻 UI，但須達出版級質感（同 Q10）且語意一目了然；客戶名、個資、內部數據、密鑰或即時敏感內容一律先虛構、遮蔽或凍結。
- [ ] **Q2｜3D 文字走 2–4 倍高清源＋原生 CSS `zoom`**：3D 透視下的 UI 素材須以顯示尺寸 **2–4 倍**解析度準備並向下取樣（全頁 **2x** `deviceScaleFactor: 2`、特寫主角元素 **4x** 獨立截圖，推進時以 **6 格［30fps 約 0.2 秒］**交叉淡入銜接）；放大一律使用版面級 CSS `zoom`（搭配 `Tx = 960/zoom - cx`、`Ty = 540/zoom - cy`（Ty 為我方依 1080 高度類推，上游只寫 Tx） 換算焦點），嚴禁用 `transform: scale` 先降取樣再放大；文字發糊先查解析度與 `zoom` 路徑而非調景深，並逐格裁切放大確認字緣無像素方塊。
- [ ] **Q3｜亮場宣傳片零手持晃動**：亮色系 UI 產品宣傳片全面禁用手持晃動（handheld shake）；僅暗色系紀實氛圍片可使用極微小相機雜訊（判例中 `0.02` 未被投訴，屬推測邊界，不是硬上限），且須逐格檢查確認無意外抖動。
- [ ] **Q4｜反光掃光單鏡最多給主角 1 次且裁進圓角**：禁止對批次進場元素逐一加閃光（glint / sweep），單一鏡頭最多給主角元素 **1 次**高品質掃光；所有光效必須被容器 `border-radius` 與 `overflow: hidden` 嚴格裁切在圓角內不得溢出，並以原速回放確認自然耐看。
- [ ] **Q5｜開場只留單一主角與單一動作弧**：開場第一鏡只聚焦 **1 個**核心元素並走完完整起承轉落弧線（聚光→推近→懸浮→描邊光→歸位），禁止多元素同時群舞分散注意力。
- [ ] **Q6｜機位服從文字可讀性、禁全片一刀切斜拍**：列表、堆疊等高資訊密度畫面維持正面平視；含文字的卡片特寫採側向水平視角，避免大角度俯拍或仰拍壓扁字形；傾斜視角僅限情緒／敘事鏡頭並須逐鏡驗證文字清晰可讀。
- [ ] **Q7｜物件特寫具備立體四要素**：資產或卡片堆疊特寫須同時具備「側面傾斜機位＋可感知的堆疊厚度高度＋環繞運鏡（orbit）＋與主場景反差的深色材質背景（如深色拉絲金屬）」，再隨鏡頭拉遠同步銜接回主畫面。
- [ ] **Q8｜多功能結尾採發表會大合照推上峰值**：收尾將全片展示過的每項功能各取 **1 個**代表元素自四方飛入圍繞品牌字標定格，配合升降運鏡（crane）、舞台光效與粒子將視覺能量推至全片最高點（初版預設加碼一檔）。
- [ ] **Q9｜飛入元素終點必須嵌入真實版面格位**：飛入動畫結束時，元素必須落入頁面真實排版座標並隨捲動流自然延展，禁止落地後仍懸浮在頁面上方或彼此重疊穿幫。
- [ ] **Q10｜文件與報表模擬內容達出版級完整版面**：文件／報表鏡頭必須以產品原生字體與排版填滿真實密度的模擬內文，且側邊導覽欄、評論欄、頁首等周邊結構完整入鏡，嚴禁用「單張貼圖＋大字口號」敷衍。
- [ ] **Q11｜可讀文字按成片像素量測：字幕 ≥ 5% 幀高、輔助字 ≥ 3% 幀高**：依最終渲染像素驗收有效字高（`fontSize` × 祖先縮放 × 透視壓縮 `cos(rotY)`），並縮成 **480px 寬**模擬手機小窗檢查——1080p 成片敘事字幕有效字高 **≥ 56px（≥ 5.2% 幀高，建議 60px；跨尺寸通用門檻 ≥ 5% 幀高）**，副標／統計／網址等輔助字 **≥ 32px（≥ 3% 幀高）**；畫面文字只准分「純裝飾紋理（明顯虛化降亮）」與「清晰必讀（達標字高＋對比底襯）」兩態，讀不清的中間態小字一律放大或刪除，收尾網址／CTA 絕不可偏小。

### 聲音（S1–S5）
- [ ] **S1｜強鼓點電子配樂＋電影系宣傳音效，禁遊戲音包音色（不禁動作擬音）**：配樂選強節奏電子底（如 tech-house）並實際墊入成片試聽定案；音效限用宣傳片詞彙（`whoosh` 運鏡／`impact` 落地／`riser` 鋪墊／`sparkle` 光效／`transition` 轉場）與真實物件擬音（快門、機械開關、紙張、玻璃，如快門聲可給最高響度 `0.6`），嚴禁合成器 bloop、卡通彈跳、過關音階等電玩回饋音色。
- [ ] **S2｜音效集中列管；連發採雙樣本交替＋音量階梯遞減＋間隔加速**：全片音效以「時間點＋音源＋音量＋對應畫面動作註解」集中成表管理；同類元素連發防機關槍感須同時做滿三招：**雙樣本交替播放**、**音量沿序列階梯遞減**（如六連發由 `0.40 → 0.25` 遞減）、**觸發間隔隨動畫曲線同步縮短**（如 `8 格 → 3 格`），極密集處改淡出為單聲 `swoosh`（不靠變調 `playbackRate`）。
- [ ] **S3｜畫面定稿後才配音；時間軸一改全表重對**：配樂與音效排在畫面分鏡鎖定之後；只要任何鏡頭增減時長或調動順序，收尾必做「全表音效時間點逐條重對」，交付前確認零音畫錯位。
- [ ] **S4｜真實擬音優先、裁切與動作嚴格等長、輕音素材驗峰**：打字配鍵盤聲、逐項落入配單點落音，不用泛用 `swoosh` 敷衍有辨識度的動作；音效播放長度須裁切至與畫面動作嚴格等長（**> 5 秒**樣本必須明確限制播放區間，撞擊音保留自然殘響）；峰值 **< -12 dB** 的輕音素材須先換檔、正規化或提高增益（必要時 `> 1.0`）並以渲染成片驗峰，確保不被配樂淹沒。
- [ ] **S5｜音畫同步統一扣兩項延遲**：依公式 **`起播時間 = 目標峰值時間 − 音源自身峰值滯後 − 輸出管線編碼偏移`** 對齊——①輸出編碼偏移（如 48kHz AAC priming 典型約 **2048 samples ≈ 30fps 下 1.28 格／約 43ms**，不同管線嚴禁直接照搬常數）須抽成片音軌與 2–3 個尖銳音效原檔做正規化互相關實測記錄，於輸出層統一扣除；②各音源檔頭至攻擊峰值的滯後逐檔量測扣除（片頭前 **2 格**內無法全額前移屬物理邊界）。

### 文案（C1–C3）
- [ ] **C1｜畫面鎖定後逐鏡重寫文案，超過 3 秒純動畫必配短解說**：初稿文案僅作佔位，畫面定稿後須對照成片逐鏡重寫確保字畫合一；超過 **3 秒**的純動畫段落必須補上精簡說明字幕，不留無字盲看段落（僅品牌收尾鏡保持乾淨）。
- [ ] **C2｜標語寫明「對象＋具體功能名＋具體效益」並加前導字卡**：全面刪除空泛隱喻口號，標語直接點出團隊／對象、產品功能名稱與實際好處；重要功能（如報表／文件頁）出場前加 **1 張**前導字卡建立預期。
- [ ] **C3｜3D 鏡頭內的註記文字放進同一 3D 空間**：3D 畫面中的說明字必須置於同一頁面 3D 座標系（共享相機透視、`translateZ` 懸浮與落影，隨鏡頭斜拍連動，禁止平貼在 2D 螢幕表層），並以醒目大字搭配螢光筆底色（highlight）標示關鍵詞。

### 流程（P1–P4）
- [ ] **P1｜交付前自行抽格截圖與像素級自檢**：每輪修改後必須先自行渲染關鍵格截圖逐張檢查構圖、抖動、文字銳利度與穿幫（必要時裁切放大或做前後格差分 diff 自證），嚴禁自己沒看過截圖就交給使用者首檢。
- [ ] **P2｜參考片先拆解手法表再逐鏡取捨，禁單圖套全片**：參考影片須先抽格拆成動態手法清單（motion breakdown）寫入規格並逐鏡評估適配度；參考圖片只代表單一鏡頭氛圍，禁止把單張參考視角（如斜拍）硬套到全片所有鏡頭。
- [ ] **P3｜模糊回饋先確認目標，改錯整筆 commit 還原重做**：遇到「第一個標題」等指涉不明的修改要求先確認對象再動手；若改錯目標立即整筆 commit 乾淨 `revert` 後重做，不在錯誤基礎上疊補丁，每項獨立修改維持單一 commit 粒度。
- [ ] **P4｜開拍前先對齊功能清單，每種主手法與每個資訊全片只出現 1 次**：動工前先列產品核心功能清單逐一對應鏡頭防漏拍；同一種主動畫手法（如發牌飛入、堆疊、翻頁）全片只當 **1 次**主角，剪輯自檢逐鏡淘汰無新資訊的重複鏡頭與重複收尾標語。

## 三、與我們現有規則衝突的地方（對照 `ours/SKILL.md`）

逐條比對 `ours/SKILL.md` 後，共有 **6 處直接衝突或門檻差異**（採用本清單時須依下列優先順序處理）：

1. **片頭前 3–4 秒結構衝突（四段配額 ① 品牌開場 vs `SKILL.md`「起：不放標題，直接開在衝突或問題」）**
   - **Shotcraft（① 品牌開場＋R1）**：前 8–12% 先放低能量品牌字標並停留 ≥ 1 秒。
   - **我們現有 `SKILL.md`**：起段（0–4 秒）明確規定**「不放標題，直接開在衝突或問題；第 0 格就要有字（平台常拿第一格當封面）」**。
   - **取捨原則**：社群動態牆／短影音（Reels、解說獲客片）優先服從 `SKILL.md`（第 0 格直接開在衝突問題，不放純品牌片頭以免被滑走）；官網首頁或產品發表會橫式宣傳片才套用 ① 品牌開場（且第 0 格仍應可見字標以免黑格封面）。

2. **高潮位置與收尾結構衝突（④ 發表會大合照＋Q8＋C1 vs `SKILL.md`「轉／合」與單一焦點）**
   - **Shotcraft（④、Q8、C1）**：把全片能量最高峰放在最後一段「多元素四方飛入大合照＋舞台光＋粒子」，且品牌收尾鏡不加文字解說。
   - **我們現有 `SKILL.md`**：全片最重的一記視覺＋音效放在**「轉」**段；**「合」**段則是「把開頭的意象拿回來問觀眾，接**唯一一個**行動（CTA）」，且規定「焦點色只給一樣東西」。
   - **取捨原則**：多功能軟體／網站總覽片可用 Q8 大合照收尾（但仍須保留 Q11 所要求的清晰結尾網址／單一 CTA）；知識解說與單一主張轉單片維持 `SKILL.md`「轉段重擊、合段收斂單一行動」。

3. **文字落定停留秒數門檻不同（R1／R2 vs `SKILL.md`「繁體中文排版與閱讀停留」）**
   - **Shotcraft（R1、R2、呼吸字卡）**：關鍵畫面／字標落定停留 **≥ 1.0 秒**，群體排滿停留 **≥ 0.5 秒**，呼吸字卡整張約 **1.7–1.8 秒**。
   - **我們現有 `SKILL.md`**：凡要讓人讀的繁中短句落定後**至少停 1.5 秒**（超過 6 字每多 4 字 **+0.25 秒**），結尾句**至少停 2.0 秒**。
   - **取捨原則**：只要畫面含需要閱讀的繁體中文句子，一律從嚴適用 `SKILL.md`（**短句 ≥ 1.5 秒、結尾 ≥ 2.0 秒**）；僅無新增文句的純視覺卡片排滿（≥ 0.5 秒）或純英文品牌字標（≥ 1.0 秒）才用 Shotcraft 下限。

4. **內建音效庫直接衝突（S1「禁用 Kenney 遊戲音包音色」vs `SKILL.md`「Kenney 音效 CC0」與 `Tone.js`）**
