# 沒反應時：照順序查

先問學員「哪一步之後不一樣了」，再從下表找最可能的一條，**一次只改一個地方**，改完再用手機測。

| 症狀 | 最常見原因 | 怎麼查／怎麼修 |
|---|---|---|
| 手機傳了沒回覆，Verify 是 Success | 關卡沒啟用，或同時啟用了兩關 | n8n workflow 清單看 active；只留一關啟用 |
| 測試時會動、啟用後沒反應 | LINE 後台填成 Test URL | 改填 Production URL（`/webhook/line-assistant`） |
| 同一句話被回兩次 | 官方帳號的自動回應沒關 | 先核對 @ID，再關「自動回應訊息」 |
| n8n 執行紀錄停在 `LINE 回覆 API`，401 | token 貼錯，或貼成另一個帳號的 token | 重新 Issue token，更新 LINE 憑證（記得 `Bearer ` 加空格） |
| 模擬訊息測試回 400 Invalid reply token | 這是**正常**的：假事件的回覆碼本來就無效 | 代表 token 正確，可以改用手機測 |
| 讀試算表 403「Sheets API 未啟用」 | GCP 專案沒啟用 Google Sheets API | 到該專案 API 程式庫啟用，等 1 分鐘再測 |
| 讀試算表 403／404（API 已啟用） | 試算表沒共用給服務帳戶，或網址貼錯 | 共用給 `client_email`、權限「編輯者」 |
| 存服務帳戶憑證時報 asymmetric key | 私鑰是手動複製的，換行壞了 | 用 `scripts/copy_private_key.py` 重貼 |
| 關卡 4、5 偶爾回「請專人回覆」 | AI 超過 20 秒沒回，範本改走人工交接 | 屬設計：LINE 回覆碼有效時間很短（官方說法約 1 分鐘，本課未實測），不能等太久；可換較快的模型 |
| 關卡 4、5 **每次**都回「請專人回覆」 | Zen key 貼錯，或模型名稱不存在 | 看 Executions 裡 `呼叫 Zen AI` 節點：401＝key 錯（重貼 Zen 憑證）；逾時＝見上一列 |
| 改了設定但好像在別的帳號生效 | 不同後台顯示名稱不同，改錯帳號 | 一律用 @ID 核對 |

查 n8n 時看「Executions」：點進最新一筆，看停在哪個節點、錯誤訊息是什麼。學員截圖給 agent 時，請他確認畫面上沒有密鑰。
