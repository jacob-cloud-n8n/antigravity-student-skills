# Agent 團隊分派

把「一件真實工作」變成「一張可以重複跑的分派表」。**工作先於角色**——不是先建好一組角色再找事給它們做，而是先看這件工作分成哪幾段，再決定每一段交給誰。

只有一位 agent 也能跑完全程：那代表每一段都由它做，但**段落仍然要分開寫、驗收仍然不能自己驗**。之後多了第二位、第三位 agent，回到第三步重新分派即可，前面兩步不必重做。

## 成功標準

完成時應同時做到：

1. 學員手上有**一件他本週真的要做的工作**被拆成 3–6 個可交付的段落，每段有明確產出。
2. 每一段都寫下五欄：**負責什麼、禁止什麼、交付什麼、由誰驗收、驗收方拿到什麼**。
3. 分派依據是「這一段需要什麼能力」，不是「我想要幾個角色」。
4. **驗收由不是做這一段的一方執行**，且**標準在動手前就寫好**（見 3.5）；驗收結果是逐項判定，不是一句「完成」。
5. 學員能說出：現在這張表如果多一位 agent，哪一段會換人。
6. 產出一張團隊分派表與一次真實的驗收紀錄，兩份都留在學員自己的資料夾。

## 入口只問一題

> **你現在手上有幾位 agent？分別是什麼？**

不要先解釋術語，也不要先介紹角色名稱。依答案分兩條路，其餘步驟完全相同：

### 分派檔位：現在在哪一檔，下一檔會多什麼

**六個步驟每一檔都一樣要走。** 差別只在第 3 步「誰做」怎麼填，以及驗收方從哪裡來。
**現場只走學員自己的那一檔**，其他檔是他帶得走的升級路徑，不佔課堂時間。

| 檔 | 手上有什麼 | 怎麼分 | 驗收方從哪來 |
|---|---|---|---|
| **1 台** | 一台 agent（例：Codex 在桌機） | 全部段落都它做，但**段落仍分開寫** | **開一個乾淨的新對話**當驗收方，只給標準與產物、不給前文 |
| **2 台** | ＋第二台（例：Hermes 裝在本機、用 Telegram 互動） | 一台做、一台驗 | **驗的那台不參與做**，它只拿到標準與產物。桌機做、手機驗 |
| **3 檔** | ＋工作流管道（例：n8n） | ⛔ **不是再加一台做事的** | 把**重複跑的那一段**交給管道，agent 負責架設與看守，人只看結果 |

🔑 **第三檔最常被搞錯**：多一台做事只會讓驗收變忙；真正的升級是**把重複的段落自動化，把人的注意力留給判斷**。

⛔ **角色數不得超過 agent 數**，不要為了好看多寫兩個角色。

## 六個步驟

### 1. 盤點
列出現有 agent 與各自擅長什麼。寫成一行一位：名稱、擅長、目前在哪裡（哪個平台／哪個資料夾）。

### 2. 選一件真的要做的工作
⛔ **不要用練習題。** 用學員本週真的要交出去的東西——沿用他已經在跑的那件事最好，因為成果看得到。
寫下這件工作的「完成長什麼樣子」，一句話，具體到可以判定。

### 3. 拆段落，然後分派
先拆段（3–6 段），每段問一句「這一段需要什麼能力」，再決定交給誰。
**順序不可顛倒**：先有段落，才有角色。只有一位 agent 時，「誰做」全部填它。

### 3.5 先寫驗收標準，再動手做

⛔ **標準要在動手之前定，而且不能由「做這一段的人」自己定。**

把你選中那一段的驗收標準寫成獨立檔案，**與產物分開**。每一項都要能回答「做到／沒做到」，不能是「寫得好」。

🔑 **為什麼這一步不能省**：如果標準是做完之後、由做的人自己補寫的，驗收方再獨立也會全部通過——
**它拿的是作者自己的尺去量作者的產物。** 全過不代表品質好，只代表你沒有在驗。

⛔ **「12 項全過、零不通過」要當成警訊，不是成績。** 先回頭看標準是誰寫的、什麼時候寫的。

### 4. 每段寫死五欄
| 負責什麼 | 禁止什麼 | 交付什麼 | 由誰驗收 | 驗收方拿到什麼 |
|---|---|---|---|---|
| 一句話 | 最容易越界的那一件 | 具體檔案或內容 | ⛔ 不能是做這一段的那一方 | 只給「標準＋產物」；**寫明它看不到什麼** |

⛔ **第五欄不能留空。** 只寫「乾淨的新對話」是不夠的——沒寫「它看不到前面的討論」，
下一個照表做的人會直接沿用同一個對話，獨立性當場消失，而**表面上每一格都有填**。

「禁止什麼」最常被跳過，而它是這張表裡最省事的一欄——它擋掉的是事後才發現的返工。

### 5. 跑一次，然後交叉驗收

**驗收鐵則：做的人不能自己驗。**

- **有兩位以上 agent**：交給**另一位**驗。驗的那位只拿到「驗收標準 ＋ 產物」，不給它前面的討論過程。
- **只有一位 agent**：開一個**乾淨的新對話**當驗收方，一樣只給標準與產物、不給前文。
  獨立性來自「看不到前面怎麼做的」，不是來自換一台機器。
- 驗收方只能回三種結果：**通過／不通過（指出第幾項、差在哪）／無法判定（缺什麼）**。
  ⛔ 不接受「看起來不錯」。
- **最終判定由學員自己下**，不是由任何一位 agent 下。

⏱ **下限＝至少完整驗一段。** 不必每一段都開新對話驗——那在一堂課裡做不完。
選**最關鍵的那一段**跑完整流程，其餘段落在表上標「**本次未驗**」。
⛔ **「本次未驗」要寫出來，不要留空**——留空會被下一個人讀成「驗過了」。

📌 **這一步只做「第一次的最低驗收」**：確認做的人沒有自己驗、確認逐項判過。
　 完整的完成定義（DoD）、進度狀態、退修路由與升級條件**不在本技能範圍**——那是下一階段「怎麼管」的事。
　 ⛔ 不要在這裡把制度一次建完，會吃掉實際跑一次的時間。

### 6. 留痕與重新分派
把這張表與驗收結果存成一張卡，放在學員自己的工作資料夾。
之後新增了 agent，回到**第 3 步**重新分派——第 1、2 步不必重做。

## 禁止事項

- ⛔ 不要預設一組固定角色（社群、設計、SEO、投放…）再叫學員填空。那會讓他建出一個沒有工作的團隊。
- ⛔ 不要讓同一方既做又驗，**也不要讓做的人自己定驗收標準**——後者更隱蔽，因為它會全過。
- ⛔ 不要用「已完成」代替逐項判定。
- ⛔ 不要把角色數量當成進度指標——**一位 agent 跑完整套流程，比三位角色各自半成品有價值**。

## 產出物

⛔ **先決定放哪個資料夾，再叫 agent 產檔**——不指定路徑時它會丟在當下的工作目錄，
　 那通常是你的專案根目錄或家目錄，過幾天就找不到了。

1. `agent團隊分派表.md`——段落、五欄、誰做誰驗、驗收方拿得到什麼
2. `段N-驗收標準.md`——**在動手前就寫好**（見 3.5），與產物分開
3. `驗收紀錄.md`——這一次的逐項判定與最終結果
3. 一張可以貼在牆上的團隊圖（選配，資料來自分派表，不另外維護）
