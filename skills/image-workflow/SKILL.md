# 圖片製作與精準編輯

把使用者的需求轉成可核對的圖片成品。回覆預設使用繁體中文；保留使用者指定的語言、文案與風格。本技能提供製作流程，實際生圖能力來自當前工具或使用者選用的 API。

## 先判斷需求與工具

- 使用者要新圖、修改現有圖或只要提示詞？參考圖片是修改目標，還是只借用風格／場景？不要把提供參考圖一律當成修改原圖。
- 依工具清單確認實際可用的生成／編輯能力，不因產品名稱就宣稱一定能生圖。Codex 有內建 `image_gen` 時優先使用，不需額外安裝工具或設定 API 金鑰。
- 只有首次使用、缺少能力、工具失效或使用者要求教學時，讀 [首次設定引導](references/onboarding.md)。已可工作時直接製作，不反覆問環境和預算。
- 使用者只要提示詞，交付可貼用的提示詞，不生成圖片。沒有可用工具時說明限制，提供提示詞模式；不擅自改走付費 API。
- 若使用者明確指定 API／模型，讀官方文件核對權限、參數與費用。內建工具只傳其介面支援的欄位，不把 `model`、`quality`、`size` 等 API 參數當成內建參數。無法指定底層模型時如實說明，不能把結果標成已驗證 GPT Image 2.5。
- 既有 SVG、可編輯 Logo、HTML 文字排版優先改原始檔；不要為簡單程式圖表或延續向量資產而重畫一張點陣圖。

## 定義本次成品

只補齊影響結果的資料；需求已清楚就直接執行。缺少目標原圖、商品參考、必要文案或關鍵尺寸時問最少的問題，其餘可說明合理假設。

用以下欄位整理提示詞，需要才使用：

```text
成品與用途：
畫布比例／交付尺寸：
主體、動作與場景：
構圖與留白：
可見的光線、色彩、材質：
參考圖角色：圖 1＝……；圖 2＝……
文字原文與位置：「……」（或明確不含文字）
本輪要改：
必須保留：
不要出現：
```

具體需求只整理，不添加未要求的人物、物件、Logo、價格、標語或品牌色。抽象需求可以補光線、材質和構圖等可見細節。需要字句精確或文字很多時，建議生背景後用 HTML／設計工具排字；使用者仍要圖中文字，就照原文生成並逐字檢查。

四種原創範例、草圖／去背與紀錄契約見 [製作與修訂參考](references/workflows.md)，只讀本次需要的段落。

## 生成與修訂

1. 編輯本機原圖時先用可用的圖片檢視工具讀圖，再呼叫生圖工具；遠端目標無法讀取時請使用者提供原圖，不假裝看過。每張參考圖有明確角色。
2. 新圖透過可用生圖工具產出；編輯傳入真正的目標圖。Codex 內建工具有本機路徑時用 `referenced_image_paths`；只有對話圖片時用最小必要的 `num_last_images_to_include`，兩者不可同時提供。其他工具依當前介面處理。
3. 指令明列本輪修改和保留條件。多輪精修以選定上一版為輸入，一輪聚焦一項主要條件；使用者指定的一組相關修改可以一起做，不強制拆成很多次生圖。重要保留條件每輪重述。
4. 一般只產使用者要求的張數。首次教學用一張新圖＋一次修改；多個不同素材各自有提示詞，避免把整套內容擠成一張縮小拼圖。
5. 透明素材在提示中要求真正透明。API 另需設定其透明輸出參數；內建工具不杜撰參數。保留工具回傳的 Alpha，不把棋盤格當透明，也不預設 JPEG 能交付透明背景。
   已知限制：內建工具曾在局部改色實測中，把真正透明的 PNG 改成不透明 RGB／棋盤格背景。這可能是工具輸出限制，不代表使用者提示詞寫錯；須重新核對 Alpha，失敗就標待修、保留上一合格版本，依修訂上限停止，不反覆重試或交付假透明。
6. 輸出採版本名稱如 `活動圖-v001.png`、`活動圖-v002.png`；不覆寫原圖／上一版。專案使用的最終圖複製到工作區，不只引用工具暫存位置。無法取出本機檔案時可展示原生圖片，但須說明無法進行檔案檢查。
7. 維持使用者既有修訂／費用上限；未指定時首次教學最多兩次生圖，普通任務先做所需初稿，必要時至多一次針對性修正。仍未達標就交代偏差與下一選項；不為追求完美無限重試。API 上限與扣款需依使用者選定路線設定，不把建立技能視為付費授權。

## 核對後交付

先檢視輸出並與原始需求／參考圖比對：文字逐字可讀、商品形狀與標籤、人物五官／手部與姿勢、構圖及非目標區域是否改動。真實案例、實際商品與人物是否可公開，由使用者確認；生成情境不得描述成實際發生的案例。

有本機檔案且 Python＋Pillow 可用時，執行唯讀檢查程式。`SKILL_DIR` 表示這份技能實際所在目錄；`--aspect` 允許 1% 相對誤差。未指定精確尺寸就不加尺寸限制。

```bash
python3 "SKILL_DIR/scripts/check_image.py" "活動圖-v002.png"
python3 "SKILL_DIR/scripts/check_image.py" "去背商品-v001.png" --require-transparent
python3 "SKILL_DIR/scripts/check_image.py" "活動圖-v002.png" --min-width 1024 --min-height 1024 --aspect 1:1
```

程式只證明檔案可解碼、尺寸／比例與是否含可見和透明像素，不證明去背邊緣、文案、保留區域或品牌品質合格。缺少 Pillow 時依引導找既有工具；不為生圖強迫安裝 Python。檔案檢查無法執行時標「未驗證」，不得當成成功。

若必須像素完全不變，單靠生成式編輯不能保證：保留核准原始素材，建議用影像合成／排版工具定稿。除非使用者明確要求另用工具，圖片編輯使用生圖工具；不自行以 Python 修圖代替。

交件附：圖片預覽／可用檔案、最終提示詞、來源與版本關係、實際使用路線、已檢查和未通過項目。需保存設定和製作紀錄時，按參考文件的欄位契約寫進選定工作目錄；不保存金鑰或完整私人對話。

## 維護來源

方法依據 [OpenAI 圖片提示指南](https://developers.openai.com/api/docs/guides/image-prompting)；工具／API 變更時查 [生圖文件](https://developers.openai.com/api/docs/guides/image-generation)，不硬寫永久模型可用性或價格。本技能範例自行撰寫，使用者提供的文章是討論起點，未複製其正文／示意圖。
