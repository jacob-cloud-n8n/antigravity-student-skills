# 製作與修訂參考

按任務選讀：商品廣告、局部修改、多圖合成、草圖轉圖、透明去背、設定與製作紀錄。以下是原創練習範例，欄位依實際需求調整，不必全部照填。

## 商品廣告

```text
成品：4:5 直式新品活動圖。
主體：使用圖 1 的茶葉包裝，保持包裝形狀、標籤與品牌識別。
場景：淺灰桌面，右側柔和自然光，乾淨的寫實商品攝影。
構圖：商品完整入鏡，上方留標題空間。
文字：只出現一次「慢慢泡，好好喝」，深色且清楚可讀。
限制：不新增價格、優惠、Logo 或其他商品。
```

沒有原始商品圖，不能假裝知道包裝。若只做概念圖，明確記為概念；正式廣告另檢查實物、文字與可用版位。

## 局部修改

```text
目標：圖 1 是要修改的原圖。
修改：只把後方灰色牆面改為米白色。
保留：人物五官、髮型、姿勢、服裝、椅子、鏡位與原有側光不變。
限制：不新增裝飾、不改人物或家具，不新增文字。
```

對照原圖的保留區域；不把「肉眼相似」記為像素完全一致。使用者指定嚴格鎖定時建議合成收尾。

## 多圖角色與合成

```text
圖 1：要編輯的桌面場景，保留桌子、背景與鏡位。
圖 2：要放入的水壺，保留外形、顏色與把手。
圖 3：只參考柔和冷色光線，不使用其人物或物件。
修改：把圖 2 水壺放在圖 1 桌面的空白區域，比例合理，匹配接觸陰影。
限制：不複製額外水壺、不增加文字，不移動原場景其他物件。
```

輸入順序與提示中的圖號一致。若插入位置不明確、沒有空間或遮住重要內容，先澄清或指出限制。

## 草圖轉圖

```text
目標：把圖 1 的書房草圖轉成寫實室內概念圖。
保留：牆面、門窗、書桌與書架位置，原有視角與空間配置。
材質：白色牆、淺木書桌、霧黑金屬書架。
光線：窗邊柔和日光。
限制：不新增房間、家具、人物或文字。
```

草圖提供構圖意圖，不是可靠的量測或施工圖。需要真實尺寸／工程精度時保留尺寸來源並由人確認；不要把概念圖說成可直接施工的設計。

## 透明去背

指定原圖與真正透明背景，保留主體輪廓、內部細節與可讀標籤，不添加底色／棋盤格。保存 PNG／WebP 並執行 `check_image.py --require-transparent`；檢視頭髮、玻璃、陰影及邊緣，程式 Alpha 通過仍可能有去背瑕疵。全透明空圖判失敗。

## 設定與製作紀錄

技能參考路徑相對技能目錄；圖片、設定和工作紀錄放使用者工作目錄，不寫進已安裝的技能資料夾。`settings.json` 沒有金鑰欄位，也不保存完整私人對話。

設定欄位契約：

| 欄位 | 型別／用途 |
|---|---|
| `schema_version` | 整數，目前為 1 |
| `mode` | `builtin`、`api` 或 `prompt-only` |
| `output_directory` | 字串，工作目錄相對路徑優先 |
| `default_aspect` | 字串或 null；只在使用者需求未另指定時使用 |
| `model_verified` | 字串或 null；只有工具回傳／可查證設定才填模型 |
| `max_targeted_revisions` | 非負整數；不取代工具自身用量限制 |
| `onboarding_status` | `not-started`、`prompt-only`、`generation-tested`、`editing-tested` |

每輪紀錄存 `image-output/<工作名>/manifest.json`，不覆寫既有輪次。建議結構：

```json
{
  "schema_version": 1,
  "job": "週末茶品活動圖",
  "mode": "builtin",
  "model_verified": null,
  "revisions": [
    {
      "version": "v001",
      "inputs": ["茶罐原圖.png"],
      "prompt": "製作商品情境圖；保持茶罐與標籤，不新增文字。",
      "output": "茶品活動-v001.png",
      "status": "checked",
      "file_checks": {"decoded": true, "transparency": "not-required"},
      "visual_checks": {"product": "pass", "text": "not-required"},
      "unresolved": [],
      "human_acceptance": "pending"
    }
  ]
}
```

`status` 可為 `prompt-only`、`generated`、`checked`、`needs-revision` 或 `failed`。只有實際檢查過才填 pass；沒有工具／未能觀察的項目記 `unverified`，錯誤保留可去敏的原因。`human_acceptance` 由使用者確認，Agent 不代填接受。新增 timestamp 時使用實際時間與時區，不虛構生成時間／費用。

交付範例：「v002 已完成背景修改，瓶身與標籤肉眼比對保留；尺寸檢查通過。未驗證像素完全一致；請確認商品與文案可公開。」有明顯偏差就標待修並指出，不勉強宣稱全部完成。
